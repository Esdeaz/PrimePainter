# Исследование и границы реплики

Целевая версия — **Adobe Substance 3D Painter 12.2.0**, выпущенная **21 октября 2026 года**. Версия проверена по официальным [примечаниям к выпуску 12.2](https://experienceleague.adobe.com/en/docs/substance-3d-painter/using/release-notes/version-12-2) 24 октября 2026 года. Задача пользователя охватывает полную реплику этой версии; перечисленные ниже отсутствующие возможности остаются частью задачи, а не исключаются из сравнения.

Состояние оригинала изучено по документации и публичным иллюстрациям. Установленный Painter в этом сеансе не запускался. Сведения о его поведении ниже имеют статус «документировано», а не «проверено в оригинале». Локальные изображения в `references` предназначены для сравнения интерфейса; они исключены из Git и публикуемого комплекта исходников. Официальные ссылки сохранены ниже.

## Сквозные сценарии

- F01: создать проект → импортировать mesh → нарисовать → отменить/повторить → сохранить → открыть → экспортировать пригодные текстуры.
- F02: добавить fill layer → настроить PBR-каналы → изменить blending/opacity → проверить 3D и 2D.
- F03: создать маску → нарисовать/заполнить её → добавить процедурный эффект → изменить исходный слой с anchor dependency.
- F04: high/low mesh → выбрать bakers → настроить matching и cage → локально исправить cage/skew → запечь → использовать mesh maps.
- F05: импортировать UDIM → переключить Texture Sets/Tiles → рисовать через границы → экспортировать отдельные tiles.
- F06: разместить path на поверхности → изменить точки → применить ribbon/filled path → сохранить редактируемый результат.
- F07: изменить mesh снаружи → reimport → перепроецировать strokes → сравнить UV и материал.
- F08: импортировать собственные ресурсы и Substance → настроить генераторы/filters → сохранить пресет → использовать в другом проекте.

Текущий результат: F01 подтверждён импортом OBJ с несколькими материалами, реальным рисованием, undo/redo, скачиванием `.prime`, повторным открытием с идентичными картами и UV, экспортом PNG. Основные операции F02 подтверждены вычислительными тестами слоёв и масок. F03 реализован только в части обычной рисуемой маски; процедурные эффекты и anchors отсутствуют. F04–F07 не реализованы. В F08 доступен импорт bitmap в слой; Substance и переносимая библиотека пресетов не реализованы. Открытие диалога или похожий элемент интерфейса не считается подтверждением вычислительного результата.

## Подтверждённая проверка PrimePainter 0.1.0

Пройдены 29 браузерных тестов: 12 в `tests/engine.spec.ts`, 5 в `tests/viewport.spec.ts` и 12 в `tests/workflows.spec.ts`. Это число проверок, а не процент полноты Painter.

- Движок: реальные пиксели PBR, blending/opacity/visibility, маски, давление и UV-симметрия, undo/redo, resize, сохранение/декодирование карт, copy-on-write, импорт alpha, merge и отказ от некорректного merge, лимит памяти, уведомления и revisions. Замер CPU paint/composite не доказывает производительность GPU.
- Viewport: конечные UV у демонстрационных моделей, сохранение UV и material groups, отклонение испорченной модели без изменения текущей, staged import, выбор UV face/mesh/island. Отдельного успешного импортного GLB/glTF-примера в этих тестах нет.
- UI: 2D paint/erase с проверкой пикселей; 3D paint и orbit; поиск и двойной щелчок по материалу; маска; скачивание и открытие `.prime` с идентичными картами и UV; ошибочный файл; OBJ с двумя материалами; reload/recovery; text undo и modal focus; PNG-размеры и фактические каналы Unreal/URP/HDRP; защита ZIP от коллизий имён Texture Sets.
- `electron/self-check.cjs`: изоляция, permissions/navigation, источник и аргументы IPC, временная запись и замена, отмена/ошибка с очисткой, dirty close и API preload. Electron в этой проверке имитируется.
- `electron/native-check.cjs`: запущен настоящий Electron с production `file:`-страницей и реальным изолированным preload. Подтверждены совпадающие байты сохранённого `.prime`, отмена сохранения и отсутствие renderer errors. Для записи в безопасный временный каталог подменён только результат `dialog.showSaveDialog`; на этапе 0.1.0 интерфейс системного выбора файла вручную ещё не проверялся. Проверка настоящих диалогов добавлена ниже для 0.1.1.

Снимки: [браузерный рабочий стол 1600×1000](screenshots/painter-workspace.png), [настоящее окно Electron](screenshots/native-workspace.png), [упакованное приложение](screenshots/packaged-workspace.png). ## Подтверждённая проверка PrimePainter 0.1.1

Общий `npm test` прошёл **35/35 тестов**: 14 в `tests/engine.spec.ts`, 7 в `tests/viewport.spec.ts`, 12 в `tests/workflows.spec.ts`, один в `tests/shortcuts.spec.ts` и один в `tests/electron-workflows.spec.ts`. Предварительный `electron/self-check.cjs` также входит в команду; его имитационные проверки не прибавляются к числу 35.

- Движок дополнительно проверяет обновление только изменившихся каналов и прямоугольных участков карт. Viewport сохраняет материал при обновлении существующих canvas; отдельные каналы загружаются по revisions. Тесты подтверждают неизменные пиксели материала и просмотра каналов при обновлении остальных карт.
- UV wireframe кэшируется в прозрачном растровом слое. Кэш соответствует видимым физическим пикселям viewport, включая масштаб и смещение; при загрузке модели сбрасывается. Проверены сохранение вида относительно исходного рисования треугольников, повторное использование кэша и ограничение выделения памяти видимой областью при отображении 8K tile. Это проверка масштаба просмотра, а не поддержка рабочих карт 8K.
- `tests/electron-workflows.spec.ts` запускает настоящий production Electron через `file:` и изолированный preload. Он проверяет native IPC, чтение OBJ и GLB с UV, отказ/отмену без потери состояния, рисование, сохранение и экспорт. В автоматическом тесте пути возвращают подменённые результаты системных диалогов; видимость Windows UI подтверждена отдельной проверкой ниже.
- В настоящем Windows UI **без подмены путей** проверен полный сценарий при русской раскладке: `Ctrl+I` открывает видимый системный диалог → выбран OBJ → выполнено рисование → `Ctrl+S` открывает системный диалог сохранения → создан корректный `.prime` размером **147679 байт**, состояние проекта `dirty=false`. Это подтверждает фактическую работу выбора и сохранения файла, а не только вызов IPC. Пользовательская настройка shortcuts, SpaceMouse и физический планшет по-прежнему не реализованы или не проверены в указанных ниже пределах.

Локальная проверка задержки выполнена через `tests/paint-profile.cjs` в настоящем Electron: стандартный Explorer Helmet, карты 1024², NVIDIA GeForce RTX 5080 через ANGLE D3D11. Измерялись 32 кадра рисования, первые пять образцов каждой серии отброшены. До исправления средний интервал кадра составил **238.51 мс**, p95 **250.1 мс**, средний вызов `drawUV` **210.58 мс**. После исправления: интервал кадра в среднем **14.66 мс**, p95 **20.8 мс**, `drawUV` в среднем **0.01 мс**, вызов `renderer.render` в среднем **8.36 мс**. Это время кадра и вызовов приложения на данной сцене и машине; отдельное время GPU не измерялось. Качество рендера и разрешение карт не снижались. Результат не распространяется на другие GPU, большие сцены или проекты.

Заново упакованная **0.1.1 проверена**. `tests/electron-workflows.spec.ts` повторно прошёл на `release/win-unpacked/PrimePainter.exe` с подтверждённым `app.isPackaged=true`. На том же исполняемом файле отдельно пройден настоящий Windows UI: меню импорта → выбор OBJ → мазок с изменением пикселей → `Ctrl+S` в русской раскладке → видимый Save и корректный `.prime` 147679 байт, `dirty=false`; подмен диалогов не было. ## Модель и ограничения

Для Painter документированы проекты, mesh, Texture Sets, UV Tiles, многоканальные слои, маски, эффекты, ресурсы и выходные шаблоны. Их внутренние бинарные структуры и движок не изучались и здесь не воспроизводятся из закрытых исходников. PrimePainter использует собственный формат `.prime`. Чтение/запись `.spp` и исполнение `.sbsar` не реализованы; лицензированные библиотеки Adobe не включены.

Текущая реализация и фактическая проверка отслеживаются в [features.csv](features.csv). `yes` означает завершённую указанную возможность с описанными локальными пределами; `partial` — часть возможности или более узкий алгоритм; `no` — отсутствие реализации. Столбец verification разделяет тесты и статическую проверку. Исключение отсутствующих возможностей ради увеличения процента покрытия недопустимо.

Фактические пределы и отличия:

- Каналы: рисуемые Base Color, Roughness, Metallic и Height; производный Normal из 2D-градиента Height. PNG — 8 бит на канал. Emissive, opacity, произвольные каналы, импорт baked normal и полноценный tangent pipeline отсутствуют.
- Разрешение общее для всех Texture Sets: 256/512/1024/2048². 4K, 8K и индивидуальное разрешение sets/tiles отсутствуют.
- До 16 sets и 80 слоёв во всём проекте. Перед выделением памяти проверяется расчётный бюджет растров 768 MiB, включая карты слоёв, маски, выходные карты и scratch; это не ограничение всей RAM/VRAM, и все максимумы не обязательно достижимы одновременно.
- Undo — до 16 действий. Цель для удерживаемых старых canvas — 128 MiB; один шаг сохраняется даже при превышении. Redo и временные операции требуют дополнительной памяти. История не сохраняется в `.prime`.
- Модели: OBJ и GLB/самостоятельный glTF без внешних URI; до 100 MiB и 2 млн треугольников. Без UV модель видна, но не рисуется. Изображения исходного материала заменяются редактируемыми наборами; skinned mesh становится статической геометрией. UDIM и автоматическая развёртка отсутствуют.
- Bitmap import: PNG/JPEG/WebP до 32 MiB и 8192²; изображение помещается в Base Color нового paint layer. Это не импорт alpha-формы кисти и не Smart Material.
- `.prime` — собственный JSON с mesh, UV, настройками и embedded PNG. Файл при открытии ограничен 220 MB; внутренняя секция движка — 180 млн символов. Несовместимые и испорченные данные отклоняются до замены текущей модели и карт.
- Симметрия отражает U текстуры, а не мировую плоскость модели. Кисть имеет size/flow/hardness/spacing; отдельной stroke opacity нет. Доступны Normal/Multiply/Screen/Overlay с общим blending и opacity для каналов слоя. UI-панели изменяют размер и скрываются, но не имеют произвольного docking.
- Есть 16 собственных процедурных материалов и круглая alpha. SBSAR, Smart Materials/Masks, генераторы, фильтры и anchors отсутствуют. Студийное окружение встроено; HDR-import отсутствует. Пресет Glass Tinted непрозрачен.
- Фиксированные экспорты: PBR, URP, HDRP и Unreal. AO в packed maps белый; detail mask HDRP также белая; smoothness вычисляется как `1 − roughness`; DirectX normal инвертирует зелёный канал. Редактора output templates и других форматов нет. Фактическая упаковка PNG проверена; импорт этих файлов в Unity/Unreal в данном сеансе не проверялся.

Не проверены физический планшет/tilt/calibration, большие производственные mesh и проекты, расход VRAM и производительность на других GPU/сценах, все варианты imported GLB/glTF, внешние движки-потребители, принудительное отключение питания во время записи. Системные диалоги Windows проверены для сценария OBJ → рисование → сохранение `.prime` с русской раскладкой; локальный замер задержки ограничен описанной выше сценой и машиной. Сравнение с запущенным оригинальным Painter и полная функциональная паритетность остаются открытыми.
